工作原理

十三个 Agent，一份索引。

索引的最小单位是轮次：你问的问题，和得到的回答。工具调用、命令行和报错另有进程范围。 两者都落进同一个 SQLite 文件，归你所有，随时可以搬走、备份或者删掉。

搜你记得的那几个词。

只记得三个字，通常也够用。全文覆盖提问和回答，底层是 SQLite FTS5：trigram 分词器让中文短语、 子串和代码标识符都能命中，英文用 porter。精确短语加引号，多个词必须同时命中。

搜过程，不只是回复。

有时候你要的不是答案，而是那次失败。进程范围覆盖工具调用、命令行、stdout 和 stderr， 以及从中提取出来的错误行。推理内容不进索引，留下的都是真正跑过的东西。

直接跳到那一轮。

点开结果，你就回到当时那一轮，关键词还高亮着。每条结果都深链到 sessionrecall://session/<id>?turn=N，会话页上带着恢复命令， 以及一张可复制的交接卡。

设计上就是只读。

Agent 的历史记录不是拿来改的数据库。Agent 存储以只读打开，从不写入；索引是另一个文件， 随时可以丢掉。没有同步，没有账号，你的会话内容永远不会被上传。

不止检索

先能搜，再看它喂饱了什么。

六件事，全部读自同一份索引 —— 不调模型、不做摘要服务、不需要额外配置。

01

打字，列表就收窄。

不用回车，没有转圈：每敲一个键都重跑一次查询。588 个会话的全量查询只要 几毫秒，所以你可以一直打字打到答案浮出来。中文按你写的样子搜 —— 数据库打不开 会拆成 数据库 AND 打不开，而不是一整串字面量；代码标识符 支持词中间命中。

02

提问和工具调用，隔一个 Tab。

qa 搜提问和回答；process 搜它们底下的工具调用 —— 命令、文件路径， 以及让你停下来的那段报错。要找的会话通常就在后半边：你记得的是堆栈，不是引出 堆栈的那句话。

03

把会话带进另一个 Agent。

^Y 复制选中会话的交接卡：项目、resume 命令、最近的提问、最后的回答、 动过的文件和命令、工具报错。粘给另一个 agent 就能接着干 —— 因为是同一份索引， 在一个 agent 里找到的会话，就是在另一个里继续的那个。

04

一个筛选给 Agent，一个给日期。

^A 循环 agent 过滤（omp、Claude Code、Cursor…），标题栏显示当前生效的是谁。 会话标题和对话一起参与检索，所以改过名字的会话，用只存在于标题里的词也能找回来。 同样的筛选在命令行上也有 —— --agent、--from、 --to、--scope process —— 以及 JSON 输出。

05

报告，不经过模型。

session-recall brief 从索引里写出日报、周报或月报：按项目分组的 会话与轮次表、你问过的每个问题，以及每条对应的 resume 命令。周报和月报会 与上一周期对比，并对项目、Agent 和最忙时段做排行。同样的会话永远生成同样的 报告，因为它是从索引里读出来的，不是模型总结的。

06

你的 Agent 也能搜它。

session-recall setup 会往这台机器上装着的 agent 里写一个 stdio MCP server 条目和一份 agent skill，于是 agent 可以在重新解决之前，先查上个月 是怎么解的。七个只读工具，doctor 里做真实的 initialize + tools/list 握手，不上传任何东西。

安装

两分钟，第一次检索。

  1. 01

    Homebrew 一条命令安装。

    一个自包含二进制：终端界面、CLI 和 MCP server。formula 下载不打 quarantine， 无需公证、没有 xattr 那一步。Linux 包在同一个 release 页。 

    brew tap odinyu/tap
brew trust odinyu/tap   # 一次性：Homebrew 7 加载第三方 tap 前需要信任
brew install session-recall
session-recall scan     # 从磁盘上已有的东西建索引
session-recall tui      # 终端界面
  2. 02

    想要窗口？装 App。

    macOS App 是单独的 cask。它是 ad-hoc 签名、没有公证（公证要花钱买 Apple 开发者 账号），所以 Homebrew 会给它打上 quarantine，macOS 拦下第一次启动。 每份拷贝清一次标记： 

    brew install --cask session-recall-app
xattr -dr com.apple.quarantine "/Applications/Session Recall.app"
open -a "Session Recall"
  3. 03

    打开就能搜。

    App 启动时会扫描 Agent 存储，打开期间每 90 秒刷新一次索引。输入你记得的词就行， 要精确短语就加上引号。终端界面里 Tab 在提问和工具调用之间切换， ^Y 复制选中会话的交接卡。

索引在 ~/Library/Application Support/session-recall/index.db；终端界面、CLI 和 App 读的是同一份。App 需要 macOS 11+；二进制在所有平台都自带运行时。

给 Agent 用

你的 Agent 也能搜。

session-recall mcp 用 stdio 把同一份索引交给任何 MCP 客户端：不开端口，不走网络， 也不用再养一份要同步的历史。把客户端指向绝对路径就行：

MCP 服务器文档 
{
  "mcpServers": {
    "session-recall": {
      "command": "bun",
      "args": ["run", "/absolute/path/to/session-recall/src/cli.ts", "mcp"]
    }
  }
}

常见问题

装之前常问的问题。

会有数据离开我的 Mac 吗？
不会。没有账号，没有同步，也没有遥测。会话从 Agent 存储读进本地那一个 SQLite 文件， 不会有任何东西被上传。
支持哪些 Agent？
八个：omp、pi、OpenCode、Cursor、Alma、Cindy、Claude Code 和 Codex。其他 agent 两行 JSON 就能加进来。omp 和官方 pi 共用一套 JSONL 格式，其余的从各自的存储读取。 每个适配器都是只读的，也都会跳过该 Agent 的私密记录。
会改动我的历史记录吗？
不会。Agent 存储以只读方式打开，从不写入。Session Recall 只写自己的索引文件； 删掉索引的代价，也就是重新扫描那点时间。
为什么 macOS 首次启动会警告？
App 是 ad-hoc 签名，没有公证，所以 Gatekeeper 会把新拷贝当成不可信，提示应用已损坏。 每份拷贝清一次隔离属性，macOS 之后就会认它： xattr -dr com.apple.quarantine "/Applications/Session Recall.app"
选 Apple 芯片版还是 Intel 版？
Apple 芯片版 27.2 MB，Intel 版 29.9 MB，都是 v1.9.3，都需要 macOS 11 或更高版本。 不确定自己是哪台 Mac，点开苹果菜单里的“关于本机”就能看到。
有 Windows 和 Linux 版吗？
Linux 有：终端版（CLI + TUI + MCP）在同一页 release 上提供 linux-arm64 和 linux-x64 包，brew install 在 Linux 上同样可用。读得到的 Agent 是 Claude Code、Codex、OpenCode、omp 和 Cursor —— Alma、Cindy、pi 是 macOS 应用，那边没有数据。 Windows 没有：本地 Agent 存储都在 macOS 和 Linux 的路径下。
索引有多新？
App 启动时扫描，打开期间每 90 秒刷新一次。索引超过五分钟没更新时，MCP 服务器会在后台 刷新，并在每次回复里告诉你它有多旧。
有全局快捷键吗？
有。默认 ⌥⌘R，在任何应用里一键唤起窗口，再按一次隐藏。可以在应用的设置里改成别的 组合键，或者完全禁用，改动重启后生效。一个 macOS 的已知怪癖：换键之后旧注册可能还在， 重启前新旧两个组合键都能唤起。
隐藏会话是怎么回事？
隐藏只是把会话从默认搜索和侧栏视图里挪开，不删任何东西。日报周报会跳过隐藏的会话， 但深链仍能直接打开，按 id 的交接也不受影响——隐藏是筛选，不是上锁。 可以在会话页取消隐藏，也可以在侧栏「隐藏」视图里找回。
怎么更新？
通常什么都不用做：应用每六小时在后台检查一次，发现新版本会弹窗展示发布说明， 点一下「立即更新」即可安装，App 外面的索引原样复用。手动方式仍然可用： 从 Releases 下载新压缩包，替换“应用程序”里的 App，再给新拷贝清一次隔离标记。
