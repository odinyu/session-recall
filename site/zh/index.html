工作原理

八个 Agent，一份索引。

索引的最小单位是轮次：你问的问题，和得到的回答。工具调用、命令行和报错另有进程范围。 两者都落进同一个 SQLite 文件，归你所有，随时可以搬走、备份或者删掉： ~/Library/Application Support/session-recall/index.db。

搜你记得的那几个词。

只记得三个字，通常也够用。全文覆盖提问和回答，底层是 SQLite FTS5：trigram 分词器让中文短语、 子串和代码标识符都能命中，英文用 porter。精确短语加引号，多个词必须同时命中。

搜过程，不只是回复。

有时候你要的不是答案，而是那次失败。进程范围覆盖工具调用、命令行、stdout 和 stderr， 以及从中提取出来的错误行。推理内容不进索引，留下的都是真正跑过的东西。

直接跳到那一轮。

点开结果，你就回到当时那一轮，关键词还高亮着。每条结果都深链到 sessionrecall://session/<id>?turn=N，会话页上带着恢复命令， 以及一张可复制的交接卡。

设计上就是只读。

Agent 的历史记录不是拿来改的数据库。Agent 存储以只读打开，从不写入；索引是另一个文件， 随时可以丢掉。没有同步，没有账号，什么都不会离开这台 Mac。

不止检索

搜索只是开始。

找到会话只是一半。另一半是把活接着做下去：交给另一个 Agent，写进明天的站会， 该从索引里拿掉的时候再拿掉。

01

把活接着做下去。

交接卡把新会话需要的东西一次收齐：项目、恢复命令、最近几次提问、最后一次回答（原文）、 工具调用碰过的文件、跑过的命令、遇到的报错，项目是 Git worktree 时还有当前分支。 粘进草稿本，或者交给另一个 Agent，活就接着走下去，不用从头再来。跨 Agent 交接会在 对方那里开一个新会话，把这张卡当上下文，因为会话 id 只对它自己的 Agent 有意义。

02

日报和周报。

日报是当天的站会，周报是一周的汇总，都直接从索引读出来。不调模型，也没有摘要服务： 同样的会话，永远生成同样的报告。可以在应用里看，也可以下载 Markdown。 章节标题跟着界面语言走：中文界面用下面这几组，英文界面则是 Progress、Decisions、 Open threads、First task tomorrow、Overview。

standup 进展 · 决策 · 待续 · 明天第一件事 · 概览

weekly 亮点 · 按项目 · 主题与决策 · 指标 · 风险 / 阻塞 · 下周计划

bun run brief --week 2026-W46

03

让一次会话退出索引。

点忘记此会话，它就从本地索引里移除，同时记下这个 id，之后的扫描不会再把它加回来。 Agent 自己存储里的原始记录原封不动。撤销会清掉标记，下次扫描重新索引。 这不是安全擦除：索引行和全文条目会被删掉，源文件还在。日报周报是纯 Markdown，从不改写， 所以应用会把仍然提到这次会话的报告列出来，由你决定重新生成还是删除。

安装

两分钟，就能搜出第一次结果。

  1. 01

    下载、解压、拖进“应用程序”。

    Apple 芯片版和 Intel 版是同一个 App，装哪个都行。下载约 67 MB，自带运行时， 不需要先装别的东西。

  2. 02

    清除隔离标记。

    Session Recall 是 ad-hoc 签名，没有做公证，而公证要花钱买 Apple 开发者账号。 所以 macOS 会拦下第一次启动，提示应用已损坏。每份拷贝跑一次下面的命令， 之后打开就正常了： 

    xattr -dr com.apple.quarantine \
  "/Applications/Session Recall.app"
open -a "Session Recall"
# 从克隆的仓库出发，使用 CLI 与 MCP 服务器
bun run scan
bun run sr "websocket" --limit 3
bun run mcp
  3. 03

    打开就能搜。

    App 启动时会扫描 Agent 存储，打开期间每 90 秒刷新一次索引。输入你记得的词就行， 要精确短语就加上引号。

需要 macOS 11 或更高版本。打包的 App 自带运行时；只有使用 CLI、MCP 服务器或从源码构建时才需要 Bun 1.3+。
索引位置：~/Library/Application Support/session-recall/index.db

给 Agent 用

你的 Agent 也能搜。

bun run mcp 用 stdio 把同一份索引交给任何 MCP 客户端：不开端口，不走网络， 也不用再养一份要同步的历史。把客户端指向绝对路径就行：

MCP 服务器文档 
{
  "mcpServers": {
    "session-recall": {
      "command": "bun",
      "args": ["run", "/absolute/path/to/session-recall/src/cli.ts", "mcp"]
    }
  }
}

常见问题

装之前常问的问题。

会有数据离开我的 Mac 吗？
不会。没有账号，没有同步，也没有遥测。会话从 Agent 存储读进本地那一个 SQLite 文件 ~/Library/Application Support/session-recall/index.db，不会有任何东西被上传。
支持哪些 Agent？
八个：omp、pi、OpenCode、Cursor、Alma、Cindy、Claude Code 和 Codex。omp 和官方 pi 共用一套 JSONL 格式，其余的从各自的存储读取。每个适配器都是只读的，也都会跳过该 Agent 的私密记录。
会改动我的历史记录吗？
不会。Agent 存储以只读方式打开，从不写入。Session Recall 只写自己的索引文件； 删掉索引的代价，也就是重新扫描那点时间。
为什么 macOS 首次启动会警告？
App 是 ad-hoc 签名，没有公证，所以 Gatekeeper 会把新拷贝当成不可信，提示应用已损坏。 每份拷贝清一次隔离属性，macOS 之后就会认它： xattr -dr com.apple.quarantine "/Applications/Session Recall.app"
选 Apple 芯片版还是 Intel 版？
Apple 芯片版 26.7 MB，Intel 版 29.5 MB，都是 v1.4.0，都需要 macOS 11 或更高版本。 不确定自己是哪台 Mac，点开苹果菜单里的“关于本机”就能看到。
有 Windows 和 Linux 版吗？
没有。Session Recall 是 macOS 应用，读的是 macOS 上的 Agent 存储位置。 CLI 和 MCP 服务器跑在 Bun 上，但没有 Windows 或 Linux 版本。
索引有多新？
App 启动时扫描，打开期间每 90 秒刷新一次。索引超过五分钟没更新时，MCP 服务器会在后台 刷新，并在每次回复里告诉你它有多旧。
怎么更新？
从 Releases 下载新压缩包，替换“应用程序”里的 App，再给新拷贝清一次隔离标记。 索引放在 App 外面，会继续用，不用从头重扫。
