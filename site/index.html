How it works

Thirteen agents, one index.

The unit is the turn: the question you asked and the answer you got. Tool calls, shell commands and errors get a second scope of their own. Both land in one SQLite file you own, that you can move, back up or delete.

Search the words you remember.

Three half-remembered words are usually enough. Full text over prompts and answers, built on SQLite FTS5: a trigram tokenizer so Chinese phrases, substrings and code identifiers all match, and porter for English. Put an exact phrase in quotes; several terms must all match.

Search the run, not just the reply.

Sometimes the answer is not what you need; the failure is. The process scope searches tool calls, shell commands, stdout and stderr, and the error lines pulled out of them. Reasoning is excluded, so results stay about what actually ran.

Land on the exact turn.

Open a result and you are exactly where you were, terms still highlighted. Each hit deep-links to sessionrecall://session/<id>?turn=N, and the session page carries the resume command and a copyable handoff card.

Read-only by design.

Your agent history is not a database to be edited. Agent stores are opened read-only and never written to, and the index is a separate file you can throw away. No sync, no account, nothing leaving the Mac.

Beyond search

Search is only the start.

Finding the session is half the job. The rest is carrying it forward: into another agent, into tomorrow's standup, and out of the index once it should not be searched again.

01

Pick the work back up.

The handoff card collects what a fresh session needs: the project, the resume command, the last few prompts, the last answer verbatim, the files tool calls touched, the commands that ran, the errors they hit, and the Git branch when the project is a worktree. Paste it into a scratchpad or into another agent and the work carries on instead of starting over. Cross-agent handoff opens a new session there with the card as its context, because a session id only means something to its own agent.

02

Your day, written down.

A standup for the day and a rollup for the week, read straight out of the index. No model call and no summary service: the same sessions always produce the same report. Read it in the app, or download the Markdown. The section headings follow the interface language, so an English app writes the report in English and a Chinese app writes the same report in Chinese.

03

Un-index a session.

Forget this session removes it from the local index and remembers the id, so no later scan puts it back. The original transcript, in the agent's own storage, is untouched. Undo clears the mark and the next scan indexes it again. This is not secure erasure: the index rows and full-text entries go, the source file stays. Generated briefs are plain Markdown that is never rewritten, so the app lists the ones still naming that session, for you to regenerate or delete.

Install

Two minutes to your first hit.

  1. 01

    Download, unzip, drag to Applications.

    The Apple silicon and Intel builds are the same app. Once unzipped it is about 68 MB and carries its own runtime, so there is nothing to install first.

  2. 02

    Clear the quarantine flag.

    Session Recall is ad-hoc signed, not notarized: notarization needs a paid Apple Developer account. So macOS blocks the first launch and says the app is damaged. Run this once per copy and it opens normally afterwards: 

    xattr -dr com.apple.quarantine \
  "/Applications/Session Recall.app"
open -a "Session Recall"
# from a clone, for the CLI and MCP server
bun run scan
bun run sr "websocket" --limit 3
bun run mcp
  3. 03

    Open it and search.

    The app scans agent storage on boot and refreshes the index every 90 seconds while it is open. Type the words you remember. Quote them if you want the exact phrase.

macOS 11 or later. The app carries its own runtime; Bun 1.3+ is only needed for the CLI, the MCP server, or a build from source.
Index: ~/Library/Application Support/session-recall/index.db

For agents

Your agent can search too.

bun run mcp serves the same index to any MCP client over stdio: no port, no network, no second copy of your history to keep in step. Point your client at the absolute path:

MCP server docs 
{
  "mcpServers": {
    "session-recall": {
      "command": "bun",
      "args": ["run", "/absolute/path/to/session-recall/src/cli.ts", "mcp"]
    }
  }
}

Questions

What people ask first.

Does anything leave my Mac?
No. No account, no sync, no telemetry. Sessions are read from agent storage into one local SQLite file, and nothing is ever uploaded.
Which agents does it index?
Thirteen: omp, pi, OpenCode, Cursor, Alma, Cindy, Claude Code, Codex, Gemini CLI, Qwen Code, Kimi Code, Copilot CLI and Goose. omp and the official pi share a JSONL format; Gemini CLI, Qwen Code and Kimi Code each bring a format of their own, and the rest are read from their own stores. Every adapter is read-only, and each one excludes its agent's private records.
Does it modify my history?
No. Agent stores are opened read-only and are never written to. The only file Session Recall writes is its own index, and deleting that index costs you nothing but the time to rebuild it.
Why does macOS warn on first launch?
The app is ad-hoc signed rather than notarized, so Gatekeeper treats a fresh copy as untrusted and reports it as damaged. Clearing the quarantine attribute once per copy tells macOS to trust it from then on: xattr -dr com.apple.quarantine "/Applications/Session Recall.app"
Apple silicon or Intel?
The Apple silicon build is 26.8 MB and the Intel build is 29.5 MB. Both are v1.5.0 and both need macOS 11 or later. If you are not sure which Mac you have, open the Apple menu and choose “About This Mac”.
What about Windows and Linux?
No. Session Recall is a macOS app and reads agent storage from macOS locations. The CLI and the MCP server run under Bun, but there is no Windows or Linux build.
How current is the index?
The app scans on boot and refreshes every 90 seconds while it is open. The MCP server refreshes in the background once the index is more than five minutes old, and reports its age with every reply.
How do I update?
Download the newer zip from Releases, replace the app in Applications, and clear the quarantine flag on the new copy. The index lives outside the app and is reused, so nothing is re-scanned from scratch.
