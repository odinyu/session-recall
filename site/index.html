How it works

One index for eight agents.

Each session is stored as turns — the question you asked and the answer you got — plus, in a second scope, the process events around them. All of it lives in a single SQLite file you can move, back up or delete: ~/Library/Application Support/session-recall/index.db.

Search the words you remember.

Full text over prompts and answers, backed by SQLite FTS5 with a trigram tokenizer for Chinese phrases, substrings and code identifiers, falling back to porter for English. Wrap an exact phrase in quotes; multiple terms are AND-ed.

Search the run, not just the reply.

Switch to the process scope and search tool calls, shell commands, stdout and stderr, and the error lines extracted from them. Reasoning is excluded, so results stay about what actually happened.

Land on the exact turn.

Every result deep-links to sessionrecall://session/<id>?turn=N with your terms highlighted. The session page carries the exact resume command and a copyable Markdown handoff card.

Read-only by design.

The index is a separate SQLite file. Agent stores are opened read-only and never written to, and sessions never leave the Mac — there is no sync and no account.

Install

Two minutes to your first search.

  1. 01

    Download, unzip, drag to Applications.

    Take the Apple silicon build or the Intel build — both are the same app. The packaged app is about 67 MB and ships its own runtime, so nothing else needs installing first.

  2. 02

    Clear the quarantine flag.

    Session Recall is ad-hoc signed but not notarized, because notarization needs a paid Apple Developer account. macOS therefore stops the first launch and claims the app is damaged. Run this once per copy and it opens normally from then on: 

    xattr -dr com.apple.quarantine \
  "/Applications/Session Recall.app"
open -a "Session Recall"
# from a clone, for the CLI and MCP server
bun run scan
bun run sr "websocket" --limit 3
bun run mcp
  3. 03

    Open it and search.

    The app scans agent storage on boot and refreshes the index every 90 seconds while it is open. Type the words you remember — quote an exact phrase if you have one.

macOS 11 or later. The packaged app includes its own runtime; Bun 1.3+ is only needed for the CLI, the MCP server, or building from source.
Index: ~/Library/Application Support/session-recall/index.db

For agents

Your agent can search it too.

bun run mcp serves the same index to any MCP client over stdio — no port, no network. Point your client at the absolute path:

MCP server docs 
{
  "mcpServers": {
    "session-recall": {
      "command": "bun",
      "args": ["run", "/absolute/path/to/session-recall/src/cli.ts", "mcp"]
    }
  }
}

Questions

What people ask before installing.

Does anything leave my Mac?
No. There is no account, no sync and no telemetry. Sessions are read from agent storage into a local SQLite index at ~/Library/Application Support/session-recall/index.db and are never uploaded anywhere.
Which agents does it index?
Eight: omp, pi, OpenCode, Cursor, Alma, Cindy, Claude Code and Codex. omp and the official pi share a JSONL format; the others are read from their own stores. Each adapter is read-only and each one excludes its agent's private records.
Does it modify my history?
No. Agent stores are opened read-only and never written to. The only file Session Recall writes is its own index, and deleting that index only costs you the time to rebuild it.
Why does macOS warn on first launch?
The app is ad-hoc signed rather than notarized, so Gatekeeper treats a fresh copy as untrusted and reports it as damaged. Clearing the quarantine attribute once per copy — xattr -dr com.apple.quarantine "/Applications/Session Recall.app" — tells macOS to trust it from then on.
Apple silicon or Intel?
The Apple silicon build is 26.7 MB and the Intel build is 29.5 MB; both are v1.3.0 and both need macOS 11 or later. If you are not sure which Mac you have, open the Apple menu and choose “About This Mac”.
What about Windows and Linux?
No. Session Recall is a macOS app and indexes agent storage in macOS locations. The CLI and the MCP server run under Bun, but no Windows or Linux build is published.
How current is the index?
The app scans on boot and refreshes every 90 seconds while it is open. The MCP server refreshes in the background when the index is more than five minutes old, and reports how stale it is with every reply.
How do I update?
Download the newer zip from Releases, replace the app in Applications, and clear the quarantine flag again for the new copy. Your index lives outside the app and is reused, so there is nothing to re-scan from scratch.
